# Phase 8: Voice, stock, captions, and storage providers

## Implementation status

- [x] Provider interfaces and env-selected factory for TTS, stock, transcription, and storage.
- [x] Fake MP3 TTS and OpenAI TTS producing one measured MP3 per scene.
- [x] Probe the encoded speech duration and expose that duration to scene output.
- [x] Evenly timed fake captions and word-timed Whisper transcription.
- [x] ASS caption generation in 3- or 4-word events.
- [x] Local fake stock clip and portrait Pixabay search near 1080p.
- [x] Cache downloads by clip ID and broaden searches after zero results.
- [x] Rank up to ten candidates per scene and avoid reusing a selected clip.
- [x] Local-disk storage adapter with put, get, getUrl, and delete.
- [x] Three mood-tagged, procedurally generated CC0 music beds.
- [x] OpenAI TTS and Pixabay keys resolve per user from the encrypted provider vault, with the configured Pixabay key as fallback.

Provider implementations are selected by `TTS_PROVIDER`, `STOCK_PROVIDER`,
`TRANSCRIPTION_PROVIDER`, and `STORAGE_PROVIDER`. Defaults are local fakes with
`STORAGE_PROVIDER=local-disk`; real implementations are `TTS_PROVIDER=openai`,
`STOCK_PROVIDER=pixabay` (or `pexels`), and
`TRANSCRIPTION_PROVIDER=whisper-http` (or `whisper` for the CLI). The OpenAI TTS
model and voice are configurable with `TTS_MODEL` and `TTS_VOICE`.

The real TTS adapter reads a per-user `openai-tts` key from the same AES-GCM key
vault as LLM keys, writes one MP3 for each scene, and probes the MP3 to get its
actual duration. The Pixabay adapter prefers a per-user `pixabay` key from the
vault and uses `PIXABAY_API_KEY` when no user key is saved. It requests portrait
film results at least 1080 pixels wide, ranks up to ten candidates, retries
with a broader query on zero results, caches search responses for 24 hours and
downloads by Pixabay clip ID. Searches across a multi-scene plan exclude
previously selected IDs. Save a user key through the authenticated
`PUT /api/providers/keys` route with `providerId` set to `openai-tts` or
`pixabay`. Pixabay video search parameters and response fields follow the
[official Pixabay API documentation](https://pixabay.com/api/docs/#api_search_videos).
Pexels remains available as the alternative `STOCK_PROVIDER=pexels` adapter.

Whisper transcription returns word timestamps through the local Docker
`whisper-server` HTTP API (`WHISPER_SERVER_URL`, default
`http://127.0.0.1:8080`); the local CLI adapter is also available. The fake
distributes words evenly over the measured audio duration.
`transcriptWordsToAss` groups words in 3- or 4-word caption events. A small
procedural library provides calm,
uplifting, and dramatic 30-second music beds, generated by FFmpeg and tagged
CC0-1.0. The local storage adapter owns the provider library's file operations
and implements `put`, `get`, `getUrl`, and `delete`.

Run the provider smoke suite with `pnpm --filter api media:providers`, or run one
contract at a time with `pnpm --filter api media:providers -- stock` (also
`tts`, `transcription`, `storage`, and `music`). To assemble a prompt into scene
audio, stock choices, and ASS captions, run
`pnpm --filter api media:scene -- <userId> "<prompt>"`; the user must have keys
for the selected real providers saved in the vault. Run
`pnpm --filter api media:music` to create the CC0 library ahead of time.

Fakes and storage are exercised offline in the test suite and smoke script.
OpenAI TTS needs a per-user `openai-tts` key. Pixabay uses the saved `pixabay`
key first and the configured `PIXABAY_API_KEY` otherwise. Whisper uses the
running local Docker service and needs no hosted credential.
